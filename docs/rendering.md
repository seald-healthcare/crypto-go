# Rendering

How Seald Crypto for Go represents cryptographic concepts and operations. Usage examples are in [README.md](../README.md).

## Names

Every name carried in bytes or text is the Crypto API's, word for word (the Crypto API, Names and rendering): each algorithm, label, wrap purpose and refusal kind is the contract's text exactly, and so is each format string, such as `seald/v1/signature`.

Every other name is this library's, in Go's case: exported, `UpperCamelCase`, and an initialism in capitals. An operation is named for the vectors' operation it reproduces (the vectors' Layout, Operations), so `importPublicKey` is `verify.ImportPublicKey`, `recipientId` is `verify.RecipientID` and `jsonHash` is `verify.JSONHash`. An operation the vectors do not name is named for what it does, such as `open.GenerateDeviceKey`.

## Concepts

| The Crypto API | In Go |
| --- | --- |
| A part (the Crypto API, Parts) | Its package: `verify`, `sign`, `seal` and `open`. The words the parts share are the module root's, `sealdcrypto` |
| The seal that wraps `refounding-challenge` alone (the Crypto API, Parts) | `seal/refoundingchallenge.Wrap(to, challenge, context sealdcrypto.WrapContextRefoundingChallenge)`, a package of its own beside `seal`, which links no other part, so a service importing it in place of `seal` wraps no other purpose. Its context is the purpose's struct, not a `WrapContext`, so no other purpose compiles |
| An operation | A function of its part's package, or a method of what one returns. A call blocks until it is done, and a caller that wants it concurrent runs it in a goroutine of its own. A call that runs a `Signer`, `sign.Sign` and `sign.Certify`, or a `Receiver`, `open.UnwrapWith`, takes a `context.Context` first and hands it to the signer or the receiver, since a key store signs and decapsulates over a network |
| A refusal (the Crypto API, Refusals) | The operation returns `(T, error)`, the error a `*sealdcrypto.Refusal`, found with `errors.As`, whose `Kind` is a `sealdcrypto.RefusalKind` |
| A fault | A panic, whose message names the operation and the mistake and never a value. It is raised before any refusal the same call could give, whatever the input, as the Crypto API, Refusals, sets: `Certify` faults on a body with no canonical JSON under any label, `Unwrap` on an empty locator or an epoch below 1 in its context over any wrap, and `ReadJournal` on a key of another length over any lease. A content key of another length is a fault of every operation that takes one, sealing, deriving and reading, raised before anything else it checks, as the Crypto API, Content, sets. The faults of reading a segment are the one exception the Crypto API, Refusals, makes: an `*OpenedContainer`'s read raises them once `OpenContainer` has opened the container, and a range past the content once frame 0 is read and checked, as the `content` row below has it. Bytes from a wire or from storage never panic |
| A name carried as text: an algorithm, a label, a session key's algorithm, a refusal kind | A defined `string` type, with a constant for each name, named for the type and the name, whose value is the name's text: `RefusalKindAuthenticationFailed` is `"authentication-failed"`, `AlgorithmXWing` is `"x-wing"` |
| Bytes | `[]byte`. A call never keeps or changes a slice it is given, and each slice it returns is new and the caller's |
| A tuple's parts | A variadic parameter: `verify.Tuple(parts ...[]byte)` |
| An integer | `uint64` for what a tuple carries as `u64be`: a version and an epoch. `int` for a length, an offset and a count, but for a container's: a segment's length, the content's length and a range of it are `int64`, as a `ContainerSource`'s size and `io.ReaderAt`'s offsets are, so each holds every length a header gives on every platform. `ContainerInputBody.Length` stays `int`, the length of the caller's own content, which never wraps and limits only what a 32-bit caller seals |
| A UUID, such as a tenant id or a request id | `sealdcrypto.UUID`, 16 bytes as a tuple carries them, so no value that is not a UUID reaches a call. `TenantID` is `UUID`. `sealdcrypto.ParseUUID` reads its text, refusing `malformed` any form but RFC 9562's in lower case, and `UUID.String` writes it, as the Crypto API, Encoding, sets. No operation takes a UUID as text: a caller holding one so, such as a tenant expected or a lease id, reads it first, so one in another form is refused before any byte, as the Crypto API, Refusals, sets. Text an operation does take, a `Person`'s `Iss` and `Sub` and a wrap context's locator and segment, it reads first, before any byte |
| A recipient id | `sealdcrypto.RecipientID`, its 16 bytes |
| A locator | `sealdcrypto.Locator`, a defined `string` |
| Bytes in JSON (the Crypto API, Encoding) | Read into the member of the struct a reader returns, a `[]byte`, a `RecipientID` or a key's value. Base64url without padding, read strictly: bytes have one text, and padded text, another alphabet's or a trailing bit set is refused `malformed`. Where a body says base64, as an AI agent's `runtime` does, it is the standard alphabet with its padding exactly as RFC 4648, section 4, writes it, and any other text, unpadded or base64url among them, is refused `malformed` |
| A JSON value | `sealdcrypto.JSON`, an alias of `any` holding `nil`, `bool`, `string`, `float64`, the integer types, `[]any` and `map[string]any`, as `encoding/json` decodes into an `any`. A nil slice or map is empty, and only `nil` is `null`. A float64 is refused where it is not an integer, as a fraction is. Another type, `[]string` or a defined `string` among them, is a fault, so no value is written by a rule the caller did not choose. A `JSON` returned holds `int64` for every integer |
| A public key | `sealdcrypto.PublicKey`, opaque, with `Algorithm()` and `Value()`, made only by `verify.ImportPublicKey` and a private key's `PublicKey()`, so no operation takes a key that was never checked. It never changes, and `==` compares two keys. The zero `PublicKey` is no key, and an operation given it panics |
| A private key a library holds (the Crypto API, Keys) | A handle, in the part that makes it: `sign.SigningKey`, `open.ReceivingKey` and `open.DeviceKey`, each used through a pointer. Sign makes a `sign.SigningKey` three ways: `GenerateSigningKey`, `ImportSigningKey(seed, expected)`, which imports it from its signing seed as `open.ImportPrivateKey` does, and `IdentityAuthority(authoritySeed, tenant)`, which derives a tenant's identity authority, so a component that links Sign alone holds each key it signs with. A handle has no field, signs only as a `Signer`, and prints only its algorithm and recipient id under every verb, as its `Format`, `String` and `GoString` give them. Copied by value into an unexported field of a struct, where `fmt` prints its fields, it prints an address, since its secrets are behind two pointers. It is not comparable, so no key is compared with `==` or kept as a map's key: two keys are one key when their `PublicKey()`s are equal. Its private half leaves it only through `open.ExportPrivateKey`. Its `Zeroise()` wipes it, and leaves it, and every copy of its handle, the zero key: `sign.SigningKey`'s is in `sign`, which zeroises a key it returns. The root and `verify` hold none, so a service that links `verify` alone links no private key |
| A private key of any algorithm, as importing and exporting one take it | `open.PrivateKey`, an interface only `*open.ReceivingKey`, `*sign.SigningKey` and `*open.DeviceKey` satisfy, since it embeds a method of `internal/private` no other package can declare. `open.ImportPrivateKey` returns the handle of the algorithm asked for, and `open.ExportPrivateKey` takes it |
| The key a wrap is opened under | `*open.ReceivingKey`. A device key unwraps as its `Receiving()`, the `x-wing` half a wrap to it is to, so a key that only signs does not compile as one. A key held elsewhere opens a wrap as a `Receiver`, below |
| A wrap's secret, and a domain key's (the Crypto API, Wraps) | Each wrap context is one of two kinds. A `sealdcrypto.SecretWrapContext`, every purpose but `domain-key` and `epoch-link`, opens through `open.Unwrap` and `open.UnwrapWith` to the secret, a `[]byte`. A `sealdcrypto.DomainKeyWrapContext`, `WrapContextDomainKey` and `WrapContextEpochLink`, opens through `open.UnwrapDomainKey` and `open.UnwrapDomainKeyWith` alone, each taking the key digest of the epoch whose key it opens, to that domain key, an `*open.ReceivingKey`, never its seed. So a domain key unwrapped without its digest does not compile, and the seed leaves the library only through `open.ExportPrivateKey`. Every context wraps through `seal.Wrap`. The digest is checked once the wrap opens, in constant time, and one of another length is refused as a digest that differs |
| A receiver that holds its `x-wing` half elsewhere (the Crypto API, Wraps) | `open.Receiver`, an interface of `PublicKey()` and `Decapsulate(ctx, enc) ([]byte, error)`, which a hardware key store or a platform's custody implements, as `sign.Signer` is a signer's. `open.UnwrapWith(ctx, receiver, wrapped, wrapContext)` opens a wrap with the shared secret it decapsulates `enc` to, through HPKE's key schedule built here, and makes `Unwrap`'s checks in `Unwrap`'s order: the context's text, `malformed`; a `PublicKey` that cannot receive, an `ed25519+ml-dsa-65` key, `invalid-key`; a wrap of another length than 1168 bytes, or whose X25519 ephemeral is of small order, `authentication-failed`, for its own bytes, without asking the receiver; then a shared secret that is not 32 bytes and a tag that fails, `authentication-failed`. A receiver's own error is returned unchanged. `*open.ReceivingKey` and `*open.DeviceKey` implement it, and their `Decapsulate` is the holder's side: X-Wing's 32-byte shared secret of `enc`, the caller's to zeroise, refusing an `enc` that is not 1120 bytes or whose ephemeral is of small order `authentication-failed` as `Unwrap` refuses such a wrap. A key that only signs has no `Decapsulate`, so it does not compile as a key held here that receives, and is refused `invalid-key` as a `Receiver`'s `PublicKey` |
| A signer that holds its halves elsewhere (the Crypto API, Signatures) | `sign.Signer`, an interface of `PublicKey()` and `Sign(ctx, message) ([]byte, error)`, which a key store implements. `*sign.SigningKey` and `*open.DeviceKey` implement it, and their `Sign` signs only `tuple("seald/v1/signature", label, payload)` under a label v1 has, refusing any other message `malformed` or, for its label, `unsupported`, so no key this library holds signs without a label. A signer's own error is returned unchanged, as the error of `sign.Sign` |
| A label | `sealdcrypto.Label`, with a constant for each label: `LabelAgentState` is `"agent-state"`. `sign.Sign` and `verify.VerifySignature` each refuse any other `unsupported`, checked before the key and the signature |
| A verdict, which verifying a signature gives under a label v1 has | `verify.VerifySignature(key, label, payload, signature) (bool, error)`: a verdict and a nil error under a label v1 has, and `false` with a refusal, `unsupported`, under any other, so a caller that drops the error still holds `false`. A verdict of `false` is no refusal |
| A certificate's label (the Crypto API, Certificates) | `sealdcrypto.Label`. `sign.Certify` and `verify.ReadCertificate` take `LabelIdentityAuthority` and `LabelCard` alone, and refuse any other label `unsupported`, one Labels has among them, before the signer's or the issuer's key and any byte of the certificate. A type of its own would need constants of its own, a second name for each of the two labels |
| The public keys of a tenant's identity authorities, as a service that holds no anchor fetched them (the Crypto API, Certificates, step 1) | `[]sealdcrypto.PublicKey`, in `VerifyCardUnderIdentityAuthorityInput.IdentityAuthorityKeys` and `VerifyKeptCardUnderIdentityAuthorityInput.IdentityAuthorityKeys`: one key, and two during a rotation, so a card passes under either. A key given twice counts once. Each is checked to be `ed25519+ml-dsa-65`, refused `invalid-key`, before any byte of the card. A list of none, or of more than `verify.MaxIdentityAuthorities` once a key given twice counts once, is the caller's mistake and so a fault, raised before any check, as a zero `PublicKey` in it is |
| An operation's input or result of several members | A struct named for its operation and its place: `VerifyCardInput`, `ReadCertificateResult` |
| A value of one of several forms, such as a wrap context, one per wrap purpose, or a ref's value, one per kind | An interface only this library's structs satisfy, with a struct for each form, named for the interface and the form: `WrapContext`, with `WrapContextContentKey` for `content-key`, `WrapContextEpochLink` for `epoch-link`, and a struct for each other purpose, and `RefValue`, with `RefValuePerson`, `RefValueDevice` and `RefValueSubject`. The struct's type is its form, so none carries another form's fields, and a nil value, or a pointer to a struct, is a fault |
| An optional input or member | A nil pointer or slice for absent |
| An instant | `time.Time`, compared as an instant whatever its location. One read from a certificate or a body is in UTC, with whole seconds, as its one text sets. A token's time is in UTC, in whole seconds, its genTime rounded up where it gives a fraction |
| A content given or read as a stream | An `io.Reader` where a call reads it, such as a body's content, which `open.ContainerInputBody` takes with its `Length`, a content in memory as `bytes.NewReader(b)` and `len(b)`. `(*open.OpenedContainer).ContentStream` returns one, whose `Read` returns a refusal as `Content` refuses and gives each frame's plaintext only once the frame is checked |
| A container's bytes, whole or in storage | `open.ContainerSource`, and `verify.ContainerSource` for a check with no key, each an `io.ReaderAt` with `Size() int64`, which `*bytes.Reader` and `*io.SectionReader` implement, so a container in memory is `bytes.NewReader(b)`. An error its `ReadAt` returns is returned unchanged |
| An opened container | `*open.OpenedContainer`, whose header is read through methods: `Locator()`, `Version()` and `Segments()`. `ContentLength(bodyKey)` is the content's length once frame 0 is checked, which a range of `Content` is inside, and which the metadata's `size` is, where it has one |
| A setup code or a guest code as text (the Crypto API, Encoding) | `[]byte`, the code's 32 bytes and its text alike, so the caller can zeroise either with `open.Zeroise`, never a `string`. `verify.EncodeCode(code)` writes its one text, `verify.CodeTextSize` characters, and a code of another length than `verify.CodeSize` is a fault. `verify.DecodeCode(text)` reads that text alone, and refuses any other `malformed`, white space, upper case and padding among it: it removes nothing and lowers nothing, so taking what a person typed into the code's one text is the caller's. Neither branches on nor indexes a table by a character of the code |
| A recovery phrase (the Crypto API, Recovery phrase) | `[]byte`, the phrase's text, given and returned as bytes so the caller can zeroise it with `open.Zeroise`, never a `string`. `open.EncodeRecoveryPhrase(key *ReceivingKey)` writes the backup key's, from the key and never from a seed the caller holds. `open.CheckRecoveryPhrase(phrase, fingerprint)` is the one operation that reads a phrase, and returns the backup key, an `*open.ReceivingKey`, only once its key digest is `fingerprint`: decoding alone is unexported, so no caller holds a seed whose key was never checked. Taking what a person types into the phrase's one form is the caller's |
| A body of the Crypto API, Bodies | One function of `verify` for each body, named for it, taking its bytes as signed and returning a struct of its members: `ReadIdentityAuthorityBody`, `ReadSessionBody`, `ReadCardBody`, `ReadEnrolmentRequestBody`, `ReadRotationRequestBody`, `ReadApprovalBody`, `ReadInvitationBody`, `ReadRegistrationBody`, `ReadDeviceCallBody`, `ReadUnlockBody`, `ReadEpochBody`, `ReadEscrowCommitBody`, `ReadRecordRecipientCommitBody`, `ReadTokenisationKeyBackfillBody`, `ReadOwnershipBody`, `ReadMoveBody`, `ReadCommitBody`, `ReadRevocationBody`, `ReadPersonStateBody`, `ReadRoleBody`, `ReadPasskeyBody`, `ReadAccountBody`, `ReadAgentStateBody`, `ReadSessionManifestBody` and `ReadRecoveryBody`. A reader is told which body it reads, so the caller picks the function for the body it expects, and no reader picks one by the bytes or by a label. `IdentityAuthorityBody` and `CardBody` are the structs `VerifyIdentityAuthority` and `VerifyCard` return |
| One label, two bodies: `enrolment`'s enrolment request and rotation request | One reader for each body, never one for the label: `ReadEnrolmentRequestBody` and `ReadRotationRequestBody`, the second reading the rotation request alike under `rotation` and under `enrolment` |
| One body, four labels: the commit on a key domain's escrow under `share`, `backfill`, `join` and `delegation` | One reader, `verify.ReadEscrowCommitBody`, returning `EscrowCommitBody`, which names no label: the caller verifies the signature under the label its flow expects, and the body tells none apart |
| One label, several bodies: under `share`, a commit on a key domain's escrow and a record recipient's commit; under `backfill`, those two and the tokenisation key's backfill | One reader for each body, never one for the label: `ReadEscrowCommitBody` for a domain's, `ReadRecordRecipientCommitBody`, returning `RecordRecipientCommitBody`, for a record recipient's, and `ReadTokenisationKeyBackfillBody`, returning `TokenisationKeyBackfillBody`, for the tokenisation key's, so the caller picks the body its request carries, and no reader takes another's |
| A body whose `purpose`, read first, names its other members: `revocation`'s, `person-state`'s, `role`'s, `passkey`'s and `recovery`'s | One reader for the label, returning one struct of every member any of its purposes names, `RevocationBody`, `PersonStateBody`, `RoleBody`, `PasskeyBody` and `RecoveryBody`, its `Purpose` a type of its own for each label, `RevocationPurpose`, `PersonStatePurpose`, `RolePurpose`, `PasskeyPurpose` and `RecoveryPurpose`, with a constant for each purpose. A member its purpose does not name is the zero value, a pointer nil, so a caller switches on `Purpose` first. `reason` is a `RevocationReason`; `every_device` a `bool`, true alone; `passkey_id` a `*sealdcrypto.UUID`; and `credential_id` and `passkey_key` `[]byte`, never empty, `PasskeyKey` nil under `seal`, and never a `PublicKey`, since it is WebAuthn's COSE bytes, read as bytes alone. `role` is a `string`, never empty under `give` and `remove`, and `owner_minimum` a `uint64` from 1 under `set-owner-minimum`. A recovery's `domains` is a `[]sealdcrypto.Locator` in the body's order, and `all_domains` a `bool`, true alone, one of the two under `ask` and neither under `commit`; its `recovery_id` a `sealdcrypto.UUID`; its `reason_code` a `string`, never empty, and its `reference` a `string`, empty where the Owner gives none, each read for its form alone; and its `slices_hash` a `[]byte` of 32 bytes. A purpose its label does not name is refused `malformed`, whatever v1 has elsewhere |
| One label, two bodies: `manifest`'s session manifest and an export's | One reader, for the session's: `verify.ReadSessionManifestBody`, returning `SessionManifestBody`, its `Events` a `[]sealdcrypto.UUID` in the body's order, empty and not nil where the session read none. An export's manifest is the evidence pack's, which the Crypto API does not read, so no reader here takes one |
| An AI agent's `state`, and an account's `subject` | `verify.AgentState`, with a constant for each state, `AgentStatePaused`, `AgentStateFrozen` and `AgentStateActive`, in `AgentStateBody`. `subject` is a `string` in `AccountBody`, never empty, read and given as written |
| A body's `epoch` and `escrow_version`, integers from 1, and its `root` | `uint64`, as a tuple carries an epoch. `root` is a `sealdcrypto.Locator`, never empty |
| An `epoch` body's `key_digest` | `EpochBody.KeyDigest`, 32 bytes read for their form alone, which a caller gives `open.UnwrapDomainKey` for each unwrap of the epoch's key. A key opened from a slice is used only once its epoch body, rebuilt with `verify.CanonicalJSON`, verifies under `sealdcrypto.LabelEpoch` with `verify.VerifySignature`, under the signer's card checked as a kept signature's with `verify.VerifyKeptCard` or `verify.VerifyKeptCardUnderIdentityAuthority`; the library offers each step, and no operation of its own joins them, since the Crypto API, Wraps, sets them as the caller's |
| An unlock body's `requests` | `verify.UnlockBodyRequest`, in `UnlockBody.Requests` in the body's order |
| A session body's session key | `verify.SessionKey`, of its `Algorithm`, a `verify.SessionKeyAlgorithm`, and its `Value`, and not a `sealdcrypto.PublicKey`: a session key is `p-256` or `ml-dsa-65`, held by the platform's key store outside this library, and a `PublicKey` is only ever a key of an algorithm the Crypto API, Keys, lists, imported as it sets. Its value is checked for its form alone, as the Crypto API, Bodies, sets it, so a caller parses a `p-256` point with a parser that checks it is on the curve before it verifies a proof under it |
| An AI agent's attestation in a session body | `verify.SessionBody.AgentAttestation`, a `*AgentAttestation`, nil where the body holds none, of its `Measurements`, an `AgentMeasurements` of the agent's code, SDK release, model provider, model and configuration, and its `Runtime`, the bytes its base64 holds, nil where absent and empty but not nil where present and of no bytes |
| A folder index's or a pre-image journal's body, which a container's `json` seals | One call for each, never a body that may be either: `open.SealFolderIndex(w, FolderIndexInput)` under the domain root's locator, and `open.SealJournal(w, JournalInput)` under `open.JournalLocator(lease)` and version 1, each returning the body's one `SegmentCommitment`. Each takes its body as a `sealdcrypto.JSON`, and seals none its reader refuses, which is a fault |
| A timestamp token's evidence record, given or not | `evidenceRecord` of `verify.VerifyTimestamp` is nil for none, as every optional input's absence is. Any other slice, an empty one among them, is a record given, verified with the token, so a record of zero bytes is refused, as the Crypto API, Renewal, sets, and a record read from storage as empty is never taken for none |
| The clock a token's date is checked by | The platform's, read through `time.Now`, which a test fixes through a hook of the package's tests alone, so no caller can set it |
